2. CALL TRANSCRIPTS
===================
New "Calls by source" tab. Lists the individual calls for the range - caller,
time, city, answered/missed pill, first-time pill, duration. Clicking a call
expands it in place and loads its detail record: automated summary, source /
campaign / keywords / landing page / device / lead status, a link that opens
the recording in CallRail, and the transcript.

  Backend added: callrailListCalls + callrailCallDetail, both cached with the
  existing TTL policy and both routed through the new error taxonomy.

  HONEST LIMIT, and it is handled explicitly rather than hidden: CallRail
  omits the transcription field entirely when transcription is not on the
  plan. That is reported as a plan state - "Call transcription is a paid
  CallRail add-on and must be enabled on the company" - not as an error and
  not as an empty panel. Verified against three shapes: structured line
  arrays, a plain string, and the field being absent.

  The call list is loaded lazily, only when you open the tab, because it is a
  separate request and most sessions never need it. CallRail returns the 100
  most recent calls for a range; the footer says so.

3. GA4 SECTION REORDER
======================
Both GA4 views now run: cards -> interactive trend -> channel-group breakdown
-> movers/events, as asked.

  The channel-group card gets its own request whenever the chosen dimension is
  something other than channel group, so it is always present rather than only
  appearing when you happened to pick that dimension.

  BUG FOUND WHILE DOING THIS: the first implementation used blendGaRows() on a
  raw report object. That helper expects a {ok, data} response wrapper, so it
  silently returned an empty array and the card never rendered - no error, just
  a missing section. Added gaReportRows() for raw reports and rewired both
  channel cards. This is exactly the failure mode that hides in a UI.

4. AUDIT ITEMS
==============
  Average position is now impression-weighted, the way Search Console computes
  it: sum(position x impressions) / sum(impressions). On the test fixture the
  old unweighted mean returned 16.50 where the correct answer is 29.73 - a
  13-position error, and the reason the number never reconciled with the
  Search Console UI.

  Pagination: GA4 accounts and properties now follow nextPageToken (previously
  one page each, so an agency past the first page silently lost the tail).
  Account property lookups are also batched six at a time instead of run
  sequentially. CallRail accounts and companies follow the page counter to the
  end. Both have loop guards.

  Error taxonomy: classifyError() turns Google's JSON error blobs into a short
  human message plus a machine-readable code (auth_required, auth_expired,
  quota, forbidden, not_found, bad_request, server, offline) and a retryable
  flag. Every router failure goes through it, so a quota exhaustion no longer
  looks identical to a typo. Nine error shapes are covered by tests.

  - recordings and machine-generated transcripts, summaries and highlights

BEFORE YOU SUBMIT TO THE CHROME WEB STORE
=========================================
  - Verify on a live CallRail account: group_by=date, group_by=landing_page /
    keywords / referrer, /calls.json and /calls/{id}.json. Each degrades to an
    empty section rather than an error if your plan does not expose it.
  - Transcripts require the CallRail transcription add-on.
  - Multi-account Google sign-in stays dormant until you create the Web
    application OAuth client and set WEB_CLIENT_ID (see MULTI-ACCOUNT-SETUP.md).
    The privacy policy already describes that mode, so it is accurate either
    way.
  - The Google Fonts request is now disclosed. If you would rather not make it
    at all, self-host Plus Jakarta Sans and drop the fonts.googleapis.com
    entries from the CSP.
